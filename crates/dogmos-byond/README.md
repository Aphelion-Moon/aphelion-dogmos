# BYOND shim boundaries

`lib.rs` composes the shim and preserves its public Rust adapter/client paths. Public adapters
remain available because integration tests and external verification tools consume them; they
are deliberate compatibility APIs, not hidden substitutes for ownership decisions.

| Owner | Responsibility |
| --- | --- |
| `bindings/` | Existing DM proc paths, main-thread BYOND conversion and bounded requests through one production session |
| `bindings/values.rs` | Number/string list admission and typed response presentation; these functions require the BYOND calling thread |
| `dm_codec/` | Pure validated conversion between DM numeric fields and fixed-width protocol bytes, separated by message family |
| `adapter_layout/` | Maintained DM numeric record shapes, exact-word positions, units and generated reference; no runtime policy |
| `metrics.rs` | Telemetry/process observations; DreamDaemon and service accounting remain distinct |
| `diagnostics.rs` | Opt-in benchmark binds and their separate session; excluded from production generation |
| `session.rs`, `client.rs` | Exact child/worker ownership, transport, cancellation and error provenance |
| `session_limits.rs` | Negotiated capacities and time budgets, independently of wire/list layout |
| `stage_jobs.rs` | Public exact-word job adapters and request/receipt correlation |
| `binding_generation.rs` | Deterministic binding normalization and generated adapter definitions |
| `tests.rs`, `tests/` | Independent literal contracts, hostile inputs, allocation and process fixtures |

DM list positions are one-based. Rust slices are zero-based. A numeric field is either a finite
scalar, an exactly representable integer, or one unsigned 16-bit word of a larger integer.
Multiword integers are little-endian. Never reinterpret a wire byte offset as a list position.
Protocol types retain wire encoding, validation and numerical-domain authority. Adapters return
caller-legible errors for malformed lengths, tags, ranges or non-finite inputs before dispatch.
Successful conversion owns only bounded request/response data and never registers another world.

All `auxmacros::bind` entry points retain the existing `crate::ffi` panic guard. Moving a Rust
module must preserve the explicit DM proc string, macro discovery, diagnostic feature boundary
and exact generated bytes. Use the maintained `generate_bindings` example and
`tools/tests/test_generated_bindings.py`; source inventory tests follow declared modules and
retain their independent expected API lists. Supported i686 native tests and the matching DM
pair gates remain required; pure adapter success does not qualify BYOND loading.

## Adapter layout authority

`adapter_layout/` owns production numeric records by family: mixtures, metadata, topology,
callbacks/continuations, frontiers/stages/jobs and service telemetry. `process_metrics_layout.rs`
owns the versioned process-metrics record. Codecs read/write the named Rust fields; the existing
binding example emits one-based `DOGMOS_DM_*` offsets and field counts plus readable encoding,
width and unit comments. Legacy aliases retain their values, including the explicitly
**zero-relative callback event aliases**. Existing independent Rust/DM literal fixtures remain
separate from this authority. Byte-level protocol offsets and enum definitions remain in
`dogmos-protocol`; session capacities, timeouts and numerical coefficients remain elsewhere.

Variable lists compose fixed records: multi-adjust is one numeric handle followed by adjustment
pairs; frontier append/mutation is its fixed header followed by exact-word handles; callback
responses are one header followed by event records. A continuation adjustment prefixes the
ordinary adjustment list with a token. Gas/reaction metadata have parallel key/name lists and
separate product/requirement records whose owner index is zero-based. Snapshot batches and
pipenet responses share the handle-plus-snapshot record. A mixture response has four fields,
with an additional transaction identity only for the eight-field reaction response.

Legacy adapter lists contain no padding or newly introduced version word. Optional values use
their existing presence flag and canonical zero rules; wire reserved bytes are checked by the
protocol decoder and do not become DM list fields. The matched artifact ABI/protocol identity
selects these layouts. Process metrics retain their explicit version/reserved words and flags.
Unsigned wide values use little-endian 16-bit words; narrow integers and finite scalar values
keep the existing adapter validation. Optional diagnostic bindings remain isolated: their
benchmark scalars/JSON are observations, not part of the production numeric-record contract.
