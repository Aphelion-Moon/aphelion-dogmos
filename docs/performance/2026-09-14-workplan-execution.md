The service controller and bounded transport described below are now implemented. Generated contracts, native job timing/age observations and DM asynchronous mode remain open.

The service now owns one admitted job and one exact committed receipt. Submit establishes the lifecycle fence without processing a work item; Poll is read-only. Commit validates the prepared unit and current callback capacity, and replays the previous receipt before reserving or enqueueing anything. Cancellation discards unpublished work. A live gas write causes retry without overwriting the write. Reused epochs, stale identities, mixed execution and concurrent jobs are rejected. Callback reservation failures preserve ready work; an unexpected failure after core publication permanently fails the session instead of acknowledging a receipt without its events.

A dedicated I/O worker exchanges one request slot and one response slot with the world owner. Two fixed request buffers and one fixed response buffer recycle across requests. No world state or core API is accessible to the worker. The actor services queued commands FIFO and grants preparation after at most eight consecutive commands, then checks ingress again. It parks while idle/ready. The existing listener acceptance loop remains separate. Submit processing budgets include actor queue time but do not become job lifetimes. Windows cancellation covers both overlapped reads and synchronous writes; Unix uses socket shutdown. Owned workers are joined within bounded shutdown paths, and worker failures retain their diagnostic cause.
